## 语言

- 内部推理、搜索、工具调用及临时 agent 通信用英文；面向用户及供人审阅的文字用简体中文，包括文档、spec、计划、票据、PR、review 和代码注释。
- 代码标识、API、配置键、CLI 参数、schema 字段、文件名、测试名、日志与错误消息及通用技术术语保留英文。项目或外部规范指定语言时从其约定。

## 默认交付范围

- 采用符合项目规模的最小充分设计：校验与错误处理只覆盖实际会出现的情况；抽象、配置项、扩展点和兼容垫片到出现第二个使用者时再加。
- 只针对当前代码、当前数据库 schema 和新数据实现。兼容旧版本、迁移历史数据或照顾进行中的旧流程属于额外需求：先说明需求、影响与新增复杂度，获用户批准后再纳入。
- 默认目标平台为 macOS 与 Ubuntu（项目另有约定时从之）：文档、安装说明、报错提示与工具选型兼顾两者，不写死单一平台的路径或包管理器；测试与验证只在当前平台进行，不为另一平台补测试。

## 文档同步

- 变更代码时，在同一次交付中同步更新受影响的文档（README、项目文档、示例与说明性注释）；项目有文档维护规则时按其执行。

## 浏览器测试

- 自动化测试需要浏览器时，以项目开发依赖引入 Playwright，用其自带 Chromium、headless、每个测试独立的临时 context；这类测试属于 E2E 或集成测试，放在单元测试层与快速门禁之外。
- 验收（人或人指派 agent 在真实环境操作）用 harness 原生方案连接用户自己的 Chrome，复用真实登录态（Claude Code 中只用 Claude in Chrome 扩展，不用桌面 app 内置浏览器）。原生方案未连接是硬阻塞：提示用户连接，不回退到其他浏览器方案。只有 harness 本身没有原生浏览器方案时，才用 Playwright 官方 skill + CLI，登录方式以项目约定为准。
- 任何场景都不用 Playwright MCP：每次调用回传大量页面快照、挤占上下文，能力又与 skill + CLI 重复。

## 多 agent 协作

- 存在可并行的独立子任务，或需要跨多文件阅读而只要结论时，拆给子 agent；拆分成本高于收益时自己做。子 agent 可继续委派；harness 不支持子 agent 时，由主会话按同样步骤顺序完成。
- harness 支持为子 agent 指定模型时，每次调用都通过工具参数显式指定，不写进 prompt 文本代替，不依赖默认继承。各 harness 的取值：
  - Claude Code：Agent 工具的 `model` 取 haiku、sonnet、opus 之一；所有层级的子 agent 均不得使用 Fable 系列模型。
