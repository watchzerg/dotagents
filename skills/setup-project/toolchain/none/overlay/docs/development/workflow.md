## 命令与门禁

根 `justfile` 已建立命令契约，但各 recipe 尚未接入本项目的工具链，当前一律非零退出并说明原因。接入时保留 recipe 名与职责，把实现封装在 recipe 或其调用脚本内，不留空命令。

| 命令 | 职责 |
| --- | --- |
| `just check-toolchain` | 核对实际运行时与版本声明，不安装 |
| `just install` | 按锁定版本安装依赖，不升级宿主工具 |
| `just fmt [路径]` | 格式化并修复可自动修复的 lint；唯一修改文件的入口，不属于门禁 |
| `just lint` / `just typecheck` | 静态检查，不修改源码 |
| `just test [参数]` | 默认运行全部 core 测试；传参可定向 |
| `just test-full [参数]` | 运行 full 测试，经 `scripts/with_lock.py` 主机锁串行；传参可定向 |
| `just docs-check` | 文档链接、章节锚点与模块页可达性（已可用） |
| `just gate-core` | 工具链检查 → docs-check → lint → typecheck → 全部 core 测试，首错停止 |
| `just gate-full` | gate-core 后在主机锁内串行运行全部 full 测试 |

`gate-core` 可在多个 worktree 同时运行；full 测试只经 `test-full` 或 `gate-full` 运行，两者都用 `scripts/with_lock.py` 持有主机级锁自动排队。两个门禁都不接受筛选参数。

## 测试分层与资源边界

测试归属由目录、target 或 runner 与门禁入口固定维护，不由单次任务临时判断能否并行。

| 层级 | 准入 | 资源要求 |
| --- | --- | --- |
| core | 单元测试和轻量、结果确定的测试，秒级完成；不启动真实服务或桌面，不执行 E2E | 不依赖共享可变状态、固定端口、桌面焦点；可跨 worktree 并行 |
| full | 重型测试、真实基础设施集成、E2E 与需要独占资源的测试；即使已隔离也按验证范围归入 | 尽量隔离；无法隔离的资源由统一入口串行使用；成功、失败、取消路径都清理自身资源 |

<待填 按需：本项目各层的目录、target 或 runner 选择范围，以及它们被哪个 just 入口收录>

core 不以"当前恰好没冲突"作为准入证据；新增真实服务、共享状态或显著运行成本时重新分类。不得通过 skip、收集过滤或弱化断言让门禁通过，零匹配不是通过。新增或移动的测试必须被对应入口自动发现，并被无筛选的 `gate-full` 收录。
