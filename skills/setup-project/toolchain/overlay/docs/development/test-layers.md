## 分层与资源边界

测试归属由目录与门禁入口固定，不由单次任务临时判断能否并行。

| 层级 | 位置与收录 | 准入 | 资源要求 |
| --- | --- | --- | --- |
| core | {{CORE}}；由 `mise run test` 与 `gate-core` 执行 | 单元测试和轻量、结果确定的测试，秒级完成；不启动真实服务、数据库、浏览器或桌面会话，不执行 E2E | 不依赖共享可变状态、固定端口、桌面焦点或共享浏览器 Profile；可跨 worktree 并行 |
| full | {{FULL}}；出现该 stack 的测试文件即由 `gate-full` 收录，此时零收集或零匹配视为失败，目录不存在或只有其他 stack 的测试文件时提示后通过 | 重型测试、真实基础设施集成、E2E 与需要独占资源的测试，即使已隔离也按验证范围归入；需要浏览器的测试以开发依赖引入 Playwright，用自带 Chromium、headless、每个测试独立 context；需要登录时测试自备身份（现建测试用户或测试生成的 storageState，外部身份提供方用替身），不依赖真实账号、已有 cookie 或外部登录服务，依赖真实外部登录的路径留给 `/acceptance` | 尽量隔离：只监听 loopback、按实例分配端口、独立临时目录与数据库；同一主机经主机锁串行；成功、失败、取消路径都清理自身资源 |

core 的准入看 fixture、子进程和输出路径的实际副作用，不以“当前恰好没冲突”为据；新增真实服务、共享状态或显著运行成本时重新分类。

独占资源清单：当前无。新增共享服务、固定端口或桌面依赖时在此登记并归入 full。
