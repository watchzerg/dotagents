# 编码标准

code-review 按本文评审 diff。只写工具查不出的判断类标准；能机械判定的规则进 lint、typecheck 或测试。

## 通用

- 改动涉及用户可见失败、数据完整性、资源清理或凭据时，diff 必须包含对应处理，不留给调用方或下一次迭代。
- 同一规则只有一处实现，调用方消费而不复制。
- 新抽象必须比直接实现更简单；为未来需求预留的参数、hook 和层应删除。
- 命名使用 [GLOSSARY.md](GLOSSARY.md) 的术语，不用其中列为 `_Avoid_` 的同义词。
- diff 改变了模块页描述的行为、接口或代码位置（含 `covers` 范围），或让某职责的行为首次被测试覆盖，却没有按[随交付同步](docs/agents/documentation.md#随交付同步)更新或新建模块页，视为交付不完整，不以改动小豁免。
- 新增或移动的测试按[分层](docs/agents/testing.md#分层)归属，并被所属层的标准入口收录。

## 项目特定

随 retro 逐条追加，每条写清规则与判断依据。超出[体量预算](docs/agents/documentation.md#体量预算与拆页)时按主题拆到 `docs/`，在此留指针。
