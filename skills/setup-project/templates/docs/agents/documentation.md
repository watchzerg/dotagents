# 文档维护规则

本文规定文档放在哪里、写什么、多大、怎样随交付同步。读者路由在[文档索引](../INDEX.md)。

## 三态规则

每份文档只属于以下一态，不混写：

- **当前正文**：描述同一仓库版本的已实现系统，持续改写，不按迭代追加“本次增量”章节。
- **本次增量**：这次改变什么、验收什么、涉及哪些当前正文。默认由 tracker 承载；用户要求 Markdown 时放 `docs/changes/<topic>.md`。吸收进当前正文后删除：已实现的规则写入当前正文，未实现的范围转回 tracker，票据或模块页的“变更与决策来源”记下吸收位置。
- **历史证据**：ADR、调研、实验、验收记录，带时点和适用条件，不改写、不归档。唯一例外：被它链接的页面移动或拆分时只改链接目标。

代码是实际行为的证据，当前正文是预期行为的依据。两者冲突时就地记录差异并明确修代码还是修文档，不把缺陷写成正常行为，也不把待实现设计写成现状。

## 取舍原则

当前正文只写读代码得不到的内容：

- **写**：职责与边界、规则与不变量、跨文件的时序与失败收敛、状态与资源归谁、必要的设计理由。
- **不写**：目录树、源文件清单、依赖版本表、逐函数复述源码、逐个测试覆盖了什么、测试用例名与数量、票据流水、里程碑编号、commit SHA。
- **不重复**：一条规则只在归属页完整表述，其他页面一句摘要加链接；发现两处表述时合并到归属页。
- **写法**：已实现与已验证分开陈述；尚无内容的章节写一句白话说明，不留空、不编造。

## 讨论结论的落点

讨论形成明确结论时，按下节的权威落点写入，不另建会议纪要：术语进 `GLOSSARY.md`，有真实取舍的决定进 ADR，已实现行为的澄清进模块页或模块边界，尚未实现的需求进 tracker，评审中反复出现的判断类问题进 `CODING_STANDARDS.md`，工具链与门禁约定进 `docs/development/`，带时点的比较或实验进 `docs/research/`。

## 权威归属与创建时机

没有实际内容时不建占位页，也不建空目录。按任务路由只在 `AGENTS.md`，其他页面不另设。

| 信息 | 权威落点 | 创建时机 |
| --- | --- | --- |
| 跨任务约束、按任务读取入口 | `AGENTS.md` | 初始化 |
| 领域术语 | `GLOSSARY.md` | 初始化；第一个术语敲定时填入 |
| diff 评审的判断类标准 | `CODING_STANDARDS.md` | 初始化；随 retro 追加 |
| 冷启动路径、各入口回答什么 | `docs/INDEX.md` | 初始化 |
| tracker、分诊标签、领域文档写法 | `docs/agents/` 下工程 skills 的 setup 写入的文件 | 工程 skills 的 setup |
| 测试怎么写、归哪层、何时跑哪层 | `docs/agents/testing.md` | 初始化 |
| 系统全貌、功能地图、模块地图、依赖、不变量 | `docs/architecture/INDEX.md` | 初始化；用户可见功能首次被测试覆盖时在功能地图登记一行 |
| 职责归属、依赖方向、状态所有者 | `docs/architecture/module-boundaries.md` | 初始化 |
| 某模块的行为规格、实现设计、代码与验证入口 | `docs/architecture/modules/<module>.md`，见[模块页模板](#模块页模板) | 该职责的行为首次被测试覆盖时（脚手架自带的工具链测试不算），不以“还不够成熟”推迟 |
| 跨模块流程：顺序、等待点与失败收敛 | `docs/architecture/collaborations.md` | 流程涉及三个以上模块时 |
| 用户可见行为规格 | `docs/behaviors/<topic>.md`，见[行为规格模板](#行为规格模板) | 行为横跨多个模块或有非开发读者时；否则写在模块页 |
| 重要决策的背景、选择与后果 | `docs/adr/NNNN-<slug>.md`，在 [ADR 索引](../adr/INDEX.md)登记 | 第一条 ADR 时 |
| 调研、实验、验收证据 | `docs/research/`，验收放 `acceptance/`，在[调研索引](../research/INDEX.md)登记 | 按需 |
| 命令与门禁；运行时、工具链与依赖 | `docs/development/workflow.md`；`technology-stack.md` | 初始化，工具链落地后填入 |
| 测试分层合同与保留范围 | `docs/development/test-layers.md`，`/prune-tests` 按此路径读写 | 初始化；保留范围在第一次精简测试后填入 |
| 真实环境验收的环境契约 | `docs/development/local-acceptance.md`，`/acceptance` 按此路径读写 | 初始化；项目有可运行形态后填入 |
| 部署、运行配置、发布与回滚 | `docs/operations/` | 有可部署产物时 |
| Markdown 形式的增量规格 | `docs/changes/<topic>.md`，topic 用分支名或功能 slug，便于 code-review 按分支名找到 | 用户要求时；吸收后删除 |

## 模块页模板

按稳定职责划分模块，不要求与源码包一一对应。`modules/` 直接子级的每一页，六个二级标题全部必备且按序；某节尚无内容时写一句白话说明（如“本模块没有对外接口”）。节内可自由用三级标题。

```markdown
---
covers:
  - src/<module>/**
---
# 模块名称

## 定位与阅读
负责什么；不负责什么（附归属页链接）；何时读本页。其后列上级总览、依赖模块、相关规格。

## 当前行为规格
入口与前置条件、输入输出、正常流程、状态转换、不变量；失败、取消、重试、恢复。用户可见的部分按行为规格模板的四个标题作三级小节。

## 实现设计
关键协作、状态与资源所有权、事务与时序、外部副作用；必要的设计理由及 ADR 链接。

## 接口与依赖
调用者必须知道的语义，以及其他模块负责的规则链接。

## 代码与验证入口
入口文件与符号、验证它的命令或测试目录、已知限制和未验证范围。

## 变更与决策来源
已吸收的 ADR、调研、增量规格与票据编号，只用于追溯。没有时写“本页没有吸收的决策或调研”。
```

页首 `covers` 是给 `mise run docs-affected` 读的范围声明：每项是相对仓库根的 glob（`**` 跨目录，匹配到目录时算其下全部文件），frontmatter 只写 `covers:` 与其下的 `- 项`。只认领本页真正描述的源码，`src/**` 这类宽泛范围会让每次改动都命中本页；拆页后由描述该源码的子页认领；代码移动或删除时同步改。

## 行为规格模板

`docs/behaviors/` 直接子级的每一页，四个二级标题全部必备且按序；模块页“当前行为规格”里用户可见的部分用同一骨架。它从用户视角写系统做什么、之后能观察到什么，是当前正文而非增量 spec，也不是测试用例：不写测试步骤、测试数据或通过判定，也不写锁、表与列名、内部诊断码等实现细节。

```markdown
# 行为主题

## 场景与前提
谁在什么情况下使用；进入前系统应处于的状态（数据、登录态、配置）。

## 操作与可观察结果
按用户操作分三级小节：用户做什么；随后在界面或命令输出、持久化数据、文件与外部副作用上能观察到什么。

## 边界与错误情况
输入边界；失败、取消、重试时用户看到什么、系统留下什么。

## 相关模块
实现它的模块页，每项一个链接加一句职责；跨模块流程链接 `collaborations.md`。
```

多个主题共有的行为只在一页完整表述，其余页面写差异并链接。

## 体量预算与拆页

预算约束单个任务必须读入的量。`docs/research/` 与 `docs/adr/` 豁免，其余文档单页不超过 16 KB，一行（一段或一个列表项）或一个表格单元格不超过 400 字符。不设逐页豁免，超限时按[取舍原则](#取舍原则)精简或拆页：

- **模块页**：原路径保留为枢纽页，六节俱全，只留定位、子页表（子页与何时读）和共用的接口与依赖；子页放 `modules/<module>/<topic>.md`，首句写“`<模块>` 的子页：…”，分节自由，末尾保留“代码与验证入口”。
- **行为规格**：原路径保留为枢纽页，子页放 `behaviors/<topic>/`；子页说法冲突时以谁为准写在枢纽页。
- **跨模块流程**：`collaborations.md` 保留为流程表，每个流程一页放 `collaborations/`。
- **其他页面**：按读者任务拆成并列的页，在原页留链接。

拆页或移动后改全部引用，不留重定向页。

## 随交付同步

1. 动手前从架构总览找到受影响模块，读其当前正文。总览仍是 `<待填>` 而代码已存在时，先补模块地图中与改动相关的行。
2. 每个可交付切片完成时，改写受影响模块页的当前行为与设计，删除失效条款，同步 `covers`；按[创建时机](#权威归属与创建时机)新建模块页并登记模块地图。新增或拆分模块时同步模块边界；用户可见功能增删、改名或行为规格换位置时同步功能地图。
3. 术语变化更新 `GLOSSARY.md`；满足 ADR 条件的决策新增 ADR 并登记；调研结论被吸收或取代时更新调研索引的状态；使用方式改变时更新 README 或 `operations/`。
4. 完成前运行 `mise run docs-affected`（改动已提交时传基准，如 `mise run docs-affected main`），对标为“本次未修改”的页逐一判断是否要更新。交付说明列出已更新的文档与验证范围；无文档影响时写明判断。
5. 新增、移动或删除文档时同步 `docs/INDEX.md`、所属目录索引及所有引用；新文档成为某类任务的必读入口时才改 `AGENTS.md` 的表。完成后运行 `mise run docs-check`。

## 自动检查

`mise run docs-check`（`scripts/check_docs.py`）属于 `gate-core`，任何一项不符即失败。规则只写在本文，脚本只实现，调整时两处同步改。

- 本地链接的目标存在，章节锚点可解析。
- 根目录四份文档与 `docs/` 下全部 Markdown 都能从 `AGENTS.md` 沿链接到达。
- `docs/adr/` 与 `docs/research/` 下每个文件都被本目录 `INDEX.md` 直接链接。
- [体量预算](#体量预算与拆页)。
- [模块页](#模块页模板)与[行为规格](#行为规格模板)的二级标题骨架。
- 页首 `covers` 的每项至少匹配一个现存文件。

它查不出正文过时：正文与代码是否一致靠[随交付同步](#随交付同步)与 code-review，积累的漂移用 `/docs-audit` 抽页核对。

## 待填标记

初始化留下的 `<待填 时机：说明>` 是尚未成形的内容，剩余清单用下面的命令得到：

```sh
grep -rnE '<待填 (初始化|阶段3|首个模块|按需)：' --exclude-dir=.git --exclude-dir=node_modules --exclude-dir=.venv --exclude-dir=.build .
```

| 时机 | 何时可填 |
| --- | --- |
| 初始化 | 项目创建时就能回答，如一句话描述 |
| 阶段3 | 工具链、命令与门禁落地后 |
| 首个模块 | 第一个模块页按[创建时机](#权威归属与创建时机)建立后；项目已有代码时读代码填写 |
| 按需 | 说明中的条件出现时 |

填写后删除整个标记；内容尚不存在时保留，不编造。全部标记消失后删除 `AGENTS.md` 中对应的常驻约束和本节。

## 命名

主题文件用小写连字符，目录入口用 `INDEX.md`，ADR 用四位编号加小写主题，调研与验收记录带日期。源码引用用稳定文件路径与符号名，不用行号。
