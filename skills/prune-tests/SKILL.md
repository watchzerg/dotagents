# Prune Tests

大幅减少测试数量、维护成本和执行时间。默认删除非核心测试，不追求高覆盖率，不因“可能有用”保留边缘场景。

## 保留标准

- 核心单元测试（Unit Test）：验证关键业务规则或核心算法；只保留足以发现主要逻辑错误的代表性用例。
- 主流程集成测试（Integration Test）：验证用户主要任务通过实际模块协作完成，并检查关键结果。
- 已有端到端测试（End-to-End Test）或界面测试仅在承担主流程验证、且没有等效覆盖时保留。

先根据当前产品行为、架构和实现识别核心规则与主流程，不能仅凭文件名、测试名称或运行速度决定去留。

## 删除标准

大胆删除以下测试：

- 边界值、异常输入、罕见失败、故障注入及各种极端情况。
- 并发竞争、复杂时序、压力、极限容量及其组合矩阵。
- 重复验证同一规则的参数化变体和跨层重复测试。
- 与实现细节耦合的私有方法、内部调用顺序、机械快照及琐碎断言。
- 历史兼容、过时行为以及已经失去实际产品意义的回归测试。

不要因为测试涉及异常、并发或历史缺陷就自动认定它重要。
只有当相关行为本身属于产品的核心用途时，才保留最小代表性验证；
其余边缘变体仍然删除。

## 执行方式

1. 阅读项目约定、相关产品与架构文档、现有测试入口，列出核心规则和主流程。
2. 记录清理前的测试规模；条件允许时，通过现有完整测试入口记录基线结果和耗时。
3. 直接删除不符合保留标准的测试，压缩重复矩阵，并清理失去引用的测试辅助代码、数据和夹具。
4. 保留测试中的关键行为与结果断言；不得通过删断言、全量 mock 或跳过执行制造通过。
5. 检查测试发现或收集结果，运行保留测试及项目要求的相关检查。
6. 同步受影响的测试说明、执行入口和文档引用。

真正删除测试，不通过 skip、禁用测试目录或调整筛选条件隐藏测试。
只调整清理直接涉及的测试配置，不降低覆盖率门槛或取消检查来绕过失败。
默认不修改产品实现，也不顺手补回被删除的边缘测试。

已有失败应如实记录。测试去留以保留标准判断，不以能否让检查变绿判断。
清理导致的引用、导入和夹具问题应修复；发现产品缺陷时单独报告。

## 完成报告

简要说明：

- 保留的核心规则和主流程。
- 删除的主要测试类别，以及测试数量变化。
- 实际运行的检查、结果与未验证项。
- 有可比实测时，报告清理前后耗时；注明环境或缓存差异。

未运行、零匹配或失败不能算通过。不自动提交或推送。
