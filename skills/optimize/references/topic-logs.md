# 日志主题：缺失与冗余

## 调研

1. **穷举调用点。** 用 grep 列出全部日志调用点与统一出口（logger 的配置、封装函数、handler），记下总数。项目完全没有日志时不往下扫：是否引入日志是产品决定，放在那一次停顿里问用户；“不要问我”模式下不引入，在报告写明后结束。
2. **读上一轮。** 取最近一份带 `optimize-logs` 标签的 spec（含已关闭），读其“未命中的候选”。证据没变的不重提。
3. **分片探查。** 全仓库扫。按模块切片，每片派一个只读子 agent，简报见下。L1、L3、L4 查的是“该有而没有”，要沿错误路径、不可逆操作和进程入口读代码，只看已有调用点查不出来。
4. **汇总裁决。** 主 agent 合并结果，L6、L9 要跨片合起来看；回到源码复核每处命中的证据，证据不成立的移入“未命中的候选”并写明原因。

### 子 agent 简报

把占位换成实际值后下发：

> 检查 `<切片路径>` 的日志是否有缺失与冗余，逐条按 `<本文件绝对路径>` 的规则表与“不算命中”判定。只读，不改任何文件。本片的日志调用点：`<清单或 grep 命令>`。
>
> - 对每条规则回答“命中 n 处”或“未命中”。没有命中也是合格结论；不排序，不凑条数。
> - 每处命中给出 `文件:行号`。L1～L4 写出排障场景，句式为“X 失败时无法知道 Y”；L5～L7 给出数量：实测，或按代码里的间隔算出每小时多少行，并写出算式。L8 写出该事件是预期结果还是真实失败及依据；L9 列出冲突的各处；L10 指出字段，不抄录敏感值。
> - 逐个读本片的错误处理分支（`except`、`catch`、错误回调、返回错误码处）、删除、移动、覆盖操作和进程入口，判定 L1～L4。
> - 行为缺陷（与日志无关的 bug）单独列出，附代码路径。
> - 不属于任何规则的观察放在末尾“表外观察”，每条一行。

## 入选规则

规则只看代码本身。每条规则对一处代码只有命中或未命中；代码没变，再扫一遍结果为空；表外的观察不进 spec。

### 共用规则

- 每处命中附可复核的证据（`文件:行号`、实测数字或可重跑的命令），主 agent 复核后才算数。子 agent 的结论被代码推翻过不止一次。
- 调研顺带发现的行为缺陷单独建票，不混进结构 spec，在那一次停顿时列出，由用户决定是否一起做。
- “不要问我”模式不放宽规则，未命中的不会因为授权而被实现。
- 调研先读同主题上一轮 spec 的未命中清单，证据没变的不重提。

### 日志规则表

全仓库扫，日志调用点要穷举。

| 规则 | 命中判定 | 依据 |
| --- | --- | --- |
| L1 失败不可见 | 错误路径既不记日志、也不提示用户、也不向上抛 | 不吞错 |
| L2 失败无法定位 | 缺异常类型或堆栈，缺定位对象的路径或 ID，跨进程缺关联 ID，或字段被静默丢弃 | 日志要能回答哪个对象、为什么 |
| L3 不可逆操作无记录 | 删除、移动、覆盖没有记下对象与原因 | 审计 |
| L4 进程级失败不进日志 | 未捕获异常、启动失败 | 同 L1 |
| L5 空转噪声 | 空闲或轮询时周期性产生、不携带状态变化的行 | 信噪比 |
| L6 重复 | 同一事件的一次发生写出 2 行，或写到 2 个出口 | 一个事件一条记录 |
| L7 故障刷屏 | 故障期间同一错误按固定间隔无限重复 | 信噪比 |
| L8 级别错误 | 预期结果记成 WARNING 或 ERROR；真实失败记成 INFO 或更低 | 级别即告警语义 |
| L9 事件名冲突 | 两个事件同名，或一个事件两种拼写 | 可检索 |
| L10 敏感数据 | 日志里出现密钥、令牌、Cookie、口令 | 安全基线 |

- L1～L4 的每处命中写出排障场景（“X 失败时无法知道 Y”）；L5～L7 要有实测或按代码间隔算出的数量。
- 不算命中：界面已完整展示的失败、逐项成功记录、可配置日志级别、统一命名风格、没有排障场景的字段。
- 项目完全没有日志时，是否引入日志是产品决定，放在那一次停顿里问用户。

## 修复约束

规则管入选，下面几条管修完不再长出新的命中：

1. **方案自检**：spec 里的目标结构过同一张规则表。新增的日志自己要过 L5～L8。
2. **逐条报数**：调研报告逐条规则写“命中 n 处”或“未命中”，使“无需优化”可以核对。
3. **日志能在统一出口修的不逐点修。**

## 验证方式

- 只在日志的统一出口留少量测试，例如去重、限频、字段不丢、未捕获异常进日志；这几条由实现子 agent 调用 Skill `mattpocock-skills:tdd` 完成。逐个调用点的日志输出不写测试。
- 其余命中由 review 核对：收尾的 review 之外，修复子 agent 的简报要求逐处对照 spec 的命中清单确认已修，并确认新增与改动的日志过 L5～L8。
- 每票出口：`just gate-core` 退出码为 0。
- 集成分支：一次无筛选的 `just gate-full`。
