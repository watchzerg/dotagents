# 架构主题：框架结构与代码分层

调研做法改写自 Matt Pocock 的 `improve-codebase-architecture`（MIT 许可，<https://github.com/mattpocock/skills>，mattpocock/skills 1.3.1），入选改由下面的规则表判定。

## 调研

1. **取词汇。** 调用 `codebase-design`，全程使用其中的 module、interface、depth、seam、adapter、leverage、locality；领域概念用项目 `GLOSSARY.md` 的名称。为命中项设计目标结构时读它的 `DEEPENING.md`，按依赖类别决定 seam 与测试方式。
2. **读约束。** `GLOSSARY.md`、`docs/adr/` 下的 ADR、架构与分层文档。ADR 记下的决定不重新讨论，写明的约束用于判定 A5。
3. **定热区。** 列出近 30 天有 3 次以上提交的文件，不计历轮优化票自己的提交：

   ```sh
   git log --since='30 days ago' --format= --name-only \
     --invert-grep --grep='<票号 1>' --grep='<票号 2>' \
     | sed '/^$/d' | sort | uniq -c | awk '$1>=3'
   ```

   `--grep` 填带 `optimize-arch`、`optimize-docs`、`optimize-logs` 标签的全部票据（含已关闭）的编号；没有历轮票时去掉这一行。提交信息不带票号、无法剔除时，在调研报告注明“热区未排除优化提交”。
4. **分片探查。** 按模块把全仓库切片，每片一个只读子 agent。简报的主题范围为“框架结构与代码分层”，本主题补充：
   - 先调用 `codebase-design` 取词汇。
   - B 类只在这些热区文件所在的模块判定：`<热区文件清单>`。
   - 疑似浅模块先做删除测试：删掉它，复杂度是消失，还是在调用方重新出现。
5. **汇总。** 跨片的 A1、A2、A3 要合起来看。
6. **ADR 冲突。** 命中项的修复方案与某条 ADR 冲突时，在那次停顿里列出该项与冲突的 ADR，由用户决定是否重开；“不要问我”模式下该项不进 spec，在报告列出。

## 规则表

A 类是结构性缺陷，现在就有害：全仓库扫，冷热模块都入选。

| 规则 | 命中判定 | 证据 | 依据 |
| --- | --- | --- | --- |
| A1 规则重复 | 同一条业务规则（判定、计算、状态迁移、校验、调用顺序）有 3 处以上实现；或 2 处且行为已不一致。判别方法：能用一句领域语言说出这条规则，且改规则时必须同改这几处 | 那句领域语言的规则与各处实现的位置 | 单一事实来源；三次法则 |
| A2 状态多头写入 | 一份持久或共享状态被 2 个以上模块直接写，绕过它的所有者，或没有所有者 | 状态与所有写入方 | 封装；单一写入者 |
| A3 依赖方向错误 | 模块间循环依赖；或下层依赖上层，违反项目文档写明的分层 | 依赖链 | 无环依赖；依赖指向稳定方 |
| A4 死代码 | 生产路径零引用的模块、函数、参数；只为测试存在的生产方法 | 证明零引用的可重跑命令 | YAGNI |
| A5 违反成文不变量 | 项目的 ADR 或架构文档写明了约束，代码不遵守 | 文档条款与违反它的代码位置 | 文档与代码一致 |

B 类是结构性摩擦，下次改动时才付出代价：只在热区文件所在的模块入选。

| 规则 | 命中判定 | 证据 | 依据 |
| --- | --- | --- | --- |
| B1 浅模块 | 过半公开成员是纯转发，不增加行为、不变量或策略；删除测试的结果是复杂度消失 | 公开成员清单，标出纯转发的 | 深模块 |
| B2 假 seam | 接口只有一个适配器，没有东西跨它变化。生产与测试各一个算两个 | 接口与它的全部适配器 | 一个适配器是假设，两个才是真的 |
| B3 测试越过接口 | 纯计算或可本地替身的逻辑只能通过真实 I/O 或 UI 测到；或同一段装配代码被 3 个以上测试套件各抄一份 | 逻辑位置与只能触达它的测试 | 接口即测试面 |
| B4 低内聚的大单元 | 文件超过 1000 行且其中的定义能分成 2 组以上互不引用的簇；或函数超过 100 行且圈复杂度超过 15。声明式的装配和表不算 | 行数、簇的划分或圈复杂度及其测量方式 | 高内聚；数字取 pylint、SwiftLint、Sonar 的默认上限 |

不算命中：两段代码相似但表达的是两条恰好相同的规则（不会一起改）；两处未分叉的重复；改名、挪位置、换风格；为将来可能的变化加抽象。

## 修复约束

1. **整簇修完**：命中 A1 时这条规则的全部副本进同一张票，验收标准里写出证明没有残留的 grep。
2. **方案自检**：spec 里的目标结构过同一张规则表。合并重复不得造出浅模块或单适配器接口。
3. **测试精简单独成票**：结构调整使旧测试失去意义时，单开一张票，按 `/prune-tests` 的保留与删除标准处理受影响的测试。

## 验证方式

- 每张票由实现子 agent 调用 `tdd` 完成，在 spec 写明的 seam 上测试。
- 每票出口：`mise run gate-core`。
- 集成分支门禁：一次无筛选的 `mise run gate-full`。
- 收尾运行 `docs-audit` 的 diff 模式。
