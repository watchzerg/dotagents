# 文档主题：文档结构

目标是让之后的 agent 渐进式发现所需信息：从 INDEX 出发，凭条目就能判断该读哪一页，读到的页只回答一个问题。本主题只看结构；正文与代码是否一致属于 `/docs-audit`。

## 调研

1. **读约定。** `docs/agents/documentation.md` 的体量预算、拆页规则与页面模板，`docs/INDEX.md` 及各目录索引。
2. **读上一轮。** 取最近一份带 `optimize-docs` 标签的 spec（含已关闭），读其“未命中的候选”。证据没变的不重提。
3. **取机械检查的结果。** 运行 `just docs-check`。项目的 `docs-check` 已机械覆盖某条规则时，那条直接取检查结果，不再人工扫；在调研报告注明哪几条取自检查。
4. **分片探查。** 范围是当前正文页，不含调研文档、ADR 和生成的文件。按目录把页面切片，每片派一个只读子 agent，简报见下。
5. **汇总裁决。** 主 agent 合并结果，D3 要跨片合起来看；回到页面复核每处命中的证据，证据不成立的移入“未命中的候选”并写明原因。
6. **记度量。** 取 2～3 个有代表性的任务，记下完成它需要读的页数与字节数，改造后再记一次，两组数字写进报告。这只是度量，不参与入选判定。

### 子 agent 简报

把占位换成实际值后下发：

> 梳理 `<切片路径>` 下当前正文页的文档结构，逐条按 `<本文件绝对路径>` 的规则表判定。只读，不改任何文件。这几条已由 `docs-check` 覆盖，跳过：`<规则编号>`。
>
> - 对每条规则回答“命中 n 处”或“未命中”。没有命中也是合格结论；不排序，不凑条数。
> - 每处命中给出证据：`页面:行号`，加上该规则判定所需的事实。D1 给出实测字节数与预算；D2 列出各章节对应的源码范围（取 `covers`，没有时按章节引用的源文件）和读者任务；D3 给出各处陈述的位置与原文；D4 给出从 INDEX 出发找不到入链的可重跑命令；D5 引用 INDEX 条目原文；D6 给出正文中跳往历史材料的位置。
> - 发现正文与代码不符时单独列出，不判定、不修改。
> - 不属于任何规则的观察放在末尾“表外观察”，每条一行。

## 入选规则

规则只看文档本身。每条规则对一处文档只有命中或未命中；文档没变，再扫一遍结果为空；表外的观察不进 spec。

### 共用规则

- 每处命中附可复核的证据（`文件:行号`、实测数字或可重跑的命令），主 agent 复核后才算数。子 agent 的结论被代码推翻过不止一次。
- 调研顺带发现的行为缺陷单独建票，不混进结构 spec，在那一次停顿时列出，由用户决定是否一起做。
- “不要问我”模式不放宽规则，未命中的不会因为授权而被实现。
- 调研先读同主题上一轮 spec 的未命中清单，证据没变的不重提。

### 文档规则表

范围是当前正文页，不含调研文档、ADR 和生成的文件。依据列的 A1、B4 指架构主题的规则重复与低内聚的大单元。

| 规则 | 命中判定 | 依据 |
| --- | --- | --- |
| D1 超预算 | 页面或段落超过项目 `docs-check` 的预算；项目没设预算时用单页 16 KB、单行 1 KB | agent 按页读取，页面大小就是读取成本 |
| D2 多职责页 | 一页里有 2 个以上章节，各自对应的源码范围互不相交，且读者任务不同 | 一页回答一个问题；与 B4 同构 |
| D3 事实重复 | 同一条规范性事实（数值、顺序、规则）在 3 页以上完整陈述；或 2 页且已互相矛盾。索引里带链接的一句话摘要不算 | 单一事实来源；与 A1 同构 |
| D4 不可达 | 当前正文页无法从 INDEX 沿链接到达 | 渐进式发现 |
| D5 路由无判据 | INDEX 条目没有写明什么时候读这页，要打开页面才能判断是否相关 | 渐进式发现 |
| D6 正文依赖历史材料 | 当前正文页的规范性内容要跳到调研文档或变更叙述里才能读全 | 现状与历史分离 |

- 项目的 `docs-check` 已机械覆盖某条规则时，那条直接取检查结果，不再人工扫。D1、D4 已有检查的项目，本主题多数时候会以“无需优化”结束。
- “模拟任务的读取成本”不作规则：它要抽样取任务，两次扫描结果可能不同。只作为改造前后的度量写进报告。
- 正文与代码不符的转 `/docs-audit`：在报告里建议运行，不纳入本次 spec。

## 修复约束

规则管入选，下面几条管修完不再长出新的命中：

1. **方案自检**：spec 里的目标结构过同一张规则表。拆页不得造出不可达页或没有判据的 INDEX 条目，合并重复不得造出超预算页。
2. **逐条报数**：调研报告逐条规则写“命中 n 处”或“未命中”，使“无需优化”可以核对。
3. **文档的修复手段是搬动和重组内容**：新增检查项或 frontmatter 字段，只在某条规则本次命中 3 处以上、检查完全机械、不需要逐页手工维护数据时才做。靠逐页手工维护数据的检查很快会被删掉。

## 验证方式

- 实现子 agent 直接搬动和重组内容，不调用 `tdd`。搬动时同步入链、INDEX 条目与 `covers`，内容只换位置，不借机改写事实。
- 每票出口：`just docs-check` 退出码为 0。
- 集成分支：`just docs-check`，不跑 `gate-full`。本轮改了检查脚本或其他代码时改为无筛选的 `just gate-full`。
- 收尾以集成分支的基准运行 `docs-audit` 的 diff 模式，核对被搬动或受影响的页面。
