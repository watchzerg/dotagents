# 文档主题：文档结构

目标是让之后的 agent 渐进式发现所需信息：从 INDEX 出发，凭条目就能判断该读哪一页，读到的页只回答一个问题。本主题只看结构；正文与代码不符的在报告里建议运行 `/docs-audit`，不纳入本轮 spec。

范围是当前正文页，不含调研文档、ADR 和生成的文件。

## 调研

1. **读约定。** `docs/agents/documentation.md` 的体量预算、拆页规则与页面模板，`docs/INDEX.md` 及各目录索引。
2. **取机械检查的结果。** 运行 `mise run docs-check`。项目的 `docs-check` 已机械覆盖的规则直接取检查结果，不再人工扫，并在调研报告注明哪几条取自检查。D1、D4 已有检查的项目，本主题常以“无需优化”结束。
3. **分片探查。** 按目录把页面切片，每片一个只读子 agent。简报的主题范围为“当前正文页的文档结构”，本主题补充：
   - 这几条已由 `docs-check` 覆盖，跳过：`<规则编号>`。
   - 发现正文与代码不符时单独列出，不判定、不修改。
4. **汇总。** D3 要跨片合起来看。
5. **记度量。** 取 2～3 个有代表性的任务，记下完成它需要读的页数与字节数，改造后再记一次，两组数字写进报告。度量不参与入选判定。

## 规则表

D2、D3 的依据列引用架构主题的 B4、A1。

| 规则 | 命中判定 | 证据 | 依据 |
| --- | --- | --- | --- |
| D1 超预算 | 页面或段落超过项目 `docs-check` 的预算；项目没设预算时用单页 16 KB、单行 1 KB | 实测字节数与预算 | agent 按页读取，页面大小就是读取成本 |
| D2 多职责页 | 一页里有 2 个以上章节，各自对应的源码范围互不相交，且读者任务不同 | 各章节的源码范围（取 `covers`，没有时按章节引用的源文件）与读者任务 | 一页回答一个问题；与 B4 同构 |
| D3 事实重复 | 同一条规范性事实（数值、顺序、规则）在 3 页以上完整陈述；或 2 页且已互相矛盾 | 各处陈述的位置与原文 | 单一事实来源；与 A1 同构 |
| D4 不可达 | 当前正文页无法从 INDEX 沿链接到达 | 找不到入链的可重跑命令 | 渐进式发现 |
| D5 路由无判据 | INDEX 条目没有写明什么时候读这页，要打开页面才能判断是否相关 | INDEX 条目原文 | 渐进式发现 |
| D6 正文依赖历史材料 | 当前正文页的规范性内容要跳到调研文档或变更叙述里才能读全 | 正文中跳往历史材料的位置 | 现状与历史分离 |

不算命中：索引里带链接的一句话摘要。

## 修复约束

1. **方案自检**：spec 里的目标结构过同一张规则表。拆页不得造出不可达页或没有判据的 INDEX 条目，合并重复不得造出超预算页。
2. **搬动和重组内容**：一个切片是一组页面的搬动或重组，连同它的入链、INDEX 条目与 `covers`；内容只换位置，不借机改写事实。新增检查项或 frontmatter 字段，只在某条规则本次命中 3 处以上、检查完全机械、不需要逐页手工维护数据时才做。

## 验证方式

- 实现子 agent 直接搬动和重组内容，不调用 `tdd`；spec 的测试决定写“由 `docs-check` 验证”。
- 每票出口：`mise run docs-check`。
- 集成分支门禁：`mise run docs-check`；本轮改了检查脚本或其他代码时改为无筛选的 `mise run gate-full`。
- 收尾运行 `docs-audit` 的 diff 模式。
