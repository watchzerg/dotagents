# 拆票

改写自 Matt Pocock 的 `to-tickets`（MIT 许可，<https://github.com/mattpocock/skills>，插件 `mattpocock-skills` 1.3.1）。原 skill 在发布前向用户确认拆分；这里改为独立子 agent 自审。

## 步骤

1. **读 spec** 全文与评论。尚未了解相关代码时先探查；留意能让后续改动变容易的预备重构，这类票排在最前。
2. **起草。** 按[切片规则](#切片规则)把 spec 拆成票，每张票写明阻塞它的票。草稿按[票据模板](#票据模板)写进仓库之外的临时文件，此时不建票。
3. **自审。** 派一个新的子 agent，只给它 spec 编号、草稿文件路径和[自审标准](#自审标准)。它没看过拆票过程，逐票返回三项结论与修改建议。主 agent 按结论改草稿；改动涉及拆分或合并时，对改过的票再审一轮，直到三项全部通过。
4. **发布。** 按 `docs/agents/issue-tracker.md` 依阻塞顺序建票，先建阻塞方：父票为 spec，阻塞关系用 tracker 的原生依赖，标签为 `docs/agents/triage-labels.md` 中对应 `ready-for-agent` 的标签。不关闭也不改写 spec。
5. **出口。** 依赖无环（Beads 为 `bd dep cycles`），每张票的父票都是该 spec，spec 的每处命中都有票承接。命令输出留给报告。

## 切片规则

每张票是一颗曳光弹，即一个纵向切片：

- 窄而完整地穿过所涉及的每一层（存储、接口、界面、测试），不是某一层的横切。
- 做完后可以独立演示或验证，门禁通过。
- 大小装得进一个全新的上下文窗口。
- 预备重构先做。

主题上的约束：

- 命中 A1 时，这条规则的全部副本进同一张票，验收标准里写出证明没有残留的 grep。
- `arch` 主题里，结构调整使旧测试失去意义时，测试精简单独成票，按 `/prune-tests` 的保留与删除标准做。
- `docs` 主题的一个切片是一组页面的搬动或重组，连同它的入链、INDEX 条目与 `covers`。
- `logs` 主题能在统一出口修的命中合成一张票，不按调用点拆。

**大范围重构是例外。** 一次机械改动（改列名、改共享符号的类型）波及全仓库，任何纵向切片都无法单独通过门禁时，按先扩后收排序：

1. 扩：在旧形式旁加上新形式，什么都不破坏。
2. 迁：按波及范围分批迁移调用点（按包或按目录），每批一张票，被“扩”阻塞；旧形式还在，所以每批都能通过门禁。
3. 收：没有调用方后删除旧形式，这张票被所有迁移票阻塞。

连分批都无法各自通过门禁时，保持这个顺序，让各批共用集成分支，并一起阻塞最后一张“集成并验证”票，只在那里承诺门禁通过。

## 票据模板

```markdown
## 父票

<spec 编号>

## 要做什么

这张票做完后成立的端到端状态，对应 spec 的哪几处命中。不写逐层的实现清单。

## 验收标准

- [ ] 标准 1
- [ ] 标准 2
- [ ] <本主题的每票出口命令> 退出码为 0

## 阻塞于

阻塞它的票，或“无，可立即开始”。阻塞关系已用原生依赖表达时省略本节。
```

不写文件路径和代码片段，它们很快过期；需要位置时指向 spec 的“调研结果”。

## 自审标准

逐票判定三项，每项只有通过或不通过，不通过的写出修改建议：

- **大票**：一个全新的上下文窗口能读完所需材料并做完。做不完的拆开；只有几行改动、单独存在没有意义的并入相邻的票。
- **自闭环**：只凭这张票、spec 和仓库就能动手，不依赖拆票时的对话；做完后门禁通过，验收标准可用命令或观察核对。
- **依赖**：每条阻塞关系都真实存在，即不先做阻塞方就做不了或过不了门禁；没有漏掉的阻塞；整体无环；没有把可并行的票串成一条链。
