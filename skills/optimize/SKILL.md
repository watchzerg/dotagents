# 项目优化流水线

本 skill 安装在用户级，对调用时当前工作目录的项目生效。一次调用完成“调研 → spec → 拆票 → 实施 → 合并清理”，只在建 spec 之前停一次；`git push` 留给用户。

## 参数

- `arch`、`docs`、`logs`：对该主题开始新一轮。
- spec 编号：续跑这份 spec。
- 不带参数：列出三个主题与各自范围后结束。
- 参数或对话里带“不要问我”：跳过唯一的那次停顿，按推荐执行，所做假设记进 spec。它只免去确认，规则表照常适用：未命中的不实现。

一次调用只做一个主题。架构改完后另两个主题的调研结论随之过期，要全做就依次调用。

## 前提

第一步核对，缺任何一项就报告缺什么并终止：

- Beads：`bd` 可执行、项目有 `.beads/`，且 `docs/agents/issue-tracker.md` 存在。票据操作按该页执行。
- just 契约：`just --summary` 含 `gate-core` 与 `gate-full`；`docs` 主题另需 `docs-check`。
- 开始新一轮时工作树干净，且当前在默认分支。

## 判断阶段

状态落在票据里。每次调用先据此判断从哪一步开始，再读对应的参考文件：

| 票据状态 | 阶段 | 读取 |
| --- | --- | --- |
| 传主题，且没有带 `optimize-<主题>` 标签的未关闭 spec | 调研 | `references/topic-<主题>.md` |
| spec 已建，没有子票 | 拆票 | [references/tickets.md](references/tickets.md) |
| 有未关闭的子票 | 实施 | [references/implement.md](references/implement.md) |
| 子票全部关闭，spec 未关闭 | 收尾 | [references/implement.md](references/implement.md) 的收尾，从 spec 评论记录的进度接着做 |
| spec 已关闭 | 结束 | 报告“已完成”，不重做 |

传主题时已有同主题的未关闭 spec，按续跑它处理。续跑时主题取 spec 的 `optimize-<主题>` 标签，并读该主题文件的验证方式。

## 流程

1. **调研。** 按主题文件派只读子 agent 分片探查，主 agent 汇总，回到源码复核每处命中后裁决，写出调研报告：逐条规则“命中 n 处”或“未命中”。零命中时输出报告并以“无需优化”结束，不建 spec。
2. **停一次。** 把下面几项一次问完，得到回答后运行到结束：
   - 范围建议：全部命中项，以及建议本轮不做的项和理由。
   - 测试 seam。
   - 只有用户知道的事实，例如某份数据可否丢弃、某个环境当前是否可用。
   - 调研顺带发现的行为缺陷票，是否一起做。
   - 主题文件要求在这里问的产品决定。
3. **建 spec。** 按 [references/spec.md](references/spec.md)。
4. **拆票。** 按 [references/tickets.md](references/tickets.md)，含独立子 agent 的自审。
5. **实施与收尾。** 按 [references/implement.md](references/implement.md)：集成分支、每票一个 worktree 子 agent、合并、review、门禁、合入默认分支、关票、清理。
6. **报告。** 按[报告](#报告)。

主 agent 只编排：调研、实现、合并、修复都交给子 agent，自己只汇总、复核、裁决、运行门禁和操作票据，上下文只留结论。每次派子 agent 都显式指定模型。与子 agent 的往来以指针为主：spec 与票据编号、参考文件路径、提交；不复述指针能取到的内容。

## 停止规则

停顿之后只有三类阻塞会停下：

- 仓库事实互相矛盾，且无法判断以谁为准。
- 权限被拒。报告被拒的操作，原样保留现场；换一条路径达到同样效果也算绕过。
- 桌面会话锁定导致门禁或测试无法运行。立即失败并报告，不等待解锁。

其余分歧一律按推荐执行，记入报告的“代用户做出的决定”。停下时报告当前阶段与 spec 编号，之后带该编号调用即可续跑。

## 报告

固定为以下几节，没有内容的写“无”：

- **结果**：主题、spec 编号、票数；或“无需优化”。
- **调研报数**：逐条规则“命中 n 处”或“未命中”。
- **代用户做出的决定**：每项的选择与理由。
- **与 spec 的偏离**。
- **未验证项**：未运行、零匹配或失败的检查。
- **遗留票据**：行为缺陷票、`docs-audit` 转出的票及其他未关闭的票。
- **出口检查**：各阶段出口命令及其输出原文。
- **表外建议**：调研中不属于任何规则的观察，每条一行。只列出，不建票，不修改。

未运行、零匹配或失败不能算通过。
