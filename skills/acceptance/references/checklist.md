# 验收清单与账本

SKILL.md 阶段 1 推导清单、阶段 3 记录结果时按本文执行。

## 预期来源的读法

1. `docs/behaviors/<topic>.md`：每个“操作与可观察结果”段落至少对应一项；“边界与错误情况”的每条对应一项。文件没有这些章节时按段落意思拆，不要求格式。
2. `docs/architecture/modules/<module>.md` 的“当前行为规格”章节：正常流程、状态转换、失败与恢复各拆成项。被 behaviors 文件覆盖的模块行为不重复列，账本标注引用。
3. 两处都写到的行为以 behaviors 为准；互相矛盾的记入账本“疑点”，影响主流程时是硬阻塞，否则按 behaviors 验并把矛盾写进报告。
4. 文档里标 `<待填`、“尚未实现”、“计划”的内容不列入清单，记入“未覆盖”。
5. 代码里明显存在但两处文档都没写的功能不列入清单，不按代码推断预期；记入“未覆盖”，报告建议补文档。

## 验收项的内容

每项写清：

- 编号：`A-01` 起，主题模式用主题前缀如 `login-01`。
- 来源：文件路径与章节标题。
- 前提：需要的数据、登录态、配置；没有写“无”。
- 操作：用户视角的步骤，写到能照做的程度。
- 预期：按通道分列。只列契约声明的通道；文档对某通道没写预期就不列，不替文档补。
- 依赖：必须先通过的项编号；清单按依赖排序。

预期要能判断真假：“页面显示 3 条记录”“日志出现一行 `order created`”“表 `orders` 多一行且 `status=pending`”“`exports/` 下多一个 `.csv`”。文档只写了方向的（“应提示用户”），预期写成“界面出现提示文字，内容与文档一致”，并在证据里记实际文字。

## 账本

路径由阶段 0 打印。结构固定，每轮只改状态与证据，不删除项：

```markdown
# 验收账本 <项目> <日期> <all 或 topic>

契约：<docs/development/local-acceptance.md 或 "本次起草，已确认">
数据重置：<命令 或 "未重置">
基线：<时间> 日志 <文件:行数> 数据 <摘要> 可写目录 <清单>
```

状态取值：`待验`、`PASS`、`FAIL`、`FIXED`、`DEFERRED`、`阻塞`。FAIL 必须附“观察到什么、预期什么”；FIXED 只在修复后重跑通过时写。

## 轮次摘要

每轮结束打印到对话，供 goal 评估器与用户阅读，第一行固定：

```text
验收进行中：总数 24，PASS 15，FAIL 1，FIXED 2，DEFERRED 1，剩余 5；本轮修复 1；账本 /path/to/ledger.md
```

阶段 5 的最终摘要第一行改为计数，末行单独 `验收完成`。
