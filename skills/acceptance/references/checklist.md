# 验收清单与账本

## 预期来源的读法

1. `docs/behaviors/<topic>.md`：每个“操作与可观察结果”段落至少一项，“边界与错误情况”每条一项。没有这些章节时按段落意思拆。
2. `docs/architecture/modules/<module>.md` 的“当前行为规格”：正常流程、状态转换、失败与恢复各拆成项。已被 behaviors 覆盖的行为不重复列，账本标注引用。
3. 两处都写到的行为以 behaviors 为准；两处矛盾时记入“疑点”，按 behaviors 验并写进报告（影响主流程的是硬阻塞）。
4. 以下内容不列入清单，记入“未覆盖”：文档里标 `<待填`、“尚未实现”、“计划”的内容；代码里有但两处文档都没写的功能（报告建议补文档）。

## 验收项的内容

- 编号：`A-01` 起；主题模式用主题前缀，如 `login-01`。
- 来源：文件路径与章节标题。
- 前提：需要的数据、登录态、配置；没有写“无”。
- 操作：用户视角的步骤，写到能照做。
- 预期：按通道分列，只列契约声明的通道，且只写文档写到的预期。
- 依赖：必须先通过的项编号；清单按依赖排序。

预期要能判真假：“页面显示 3 条记录”“日志出现一行 `order created`”“表 `orders` 多一行且 `status=pending`”“`exports/` 下多一个 `.csv`”。文档只写了方向的（“应提示用户”），预期写“界面出现提示文字，内容与文档一致”，证据里记实际文字。

## 账本

结构固定，每轮只改状态与证据，不删项：

```markdown
# 验收账本 <项目> <日期> <all 或 topic>

契约：<docs/development/local-acceptance.md 或 "本次起草，已确认">
数据重置：<命令 或 "未重置">
基线：<时间> 日志 <文件:行数> 数据 <摘要> 可写目录 <清单>
```
