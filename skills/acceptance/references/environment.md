# 环境契约

验收只依据目标项目 `docs/development/workflow.md` 的 `## 本地运行与观测` 节操作真实环境。本文规定该节要回答什么，以及缺失时怎样起草。

## 该节要回答的问题

| 问题 | 要求 |
| --- | --- |
| 运行形态 | web 服务、CLI、后台任务、桌面应用或其组合；没有可运行形态就写明，此时验收只能走命令输出与文件 |
| 启动与停止 | 命令（通常是 just recipe）；就绪判定（端口、健康检查 URL、日志关键字或命令退出）；日志文件与 pid 文件位置。启动命令须自行后台化（`nohup`/`setsid` 加 `&`），stdout 与 stderr 全部重定向到日志文件后立即返回，否则 agent 的前台调用会挂到超时；不能依赖调用者的会话保持。停止命令要能结束全部子进程（按进程组或 pid 文件） |
| 数据 | 存储类型与位置或连接方式；查询手段（命令或工具）；重置命令。没有持久数据时写“无”。验收会写入数据并执行重置，所以指向验收专用的数据目录与库，不指向日常使用的那份；只能用日常数据时不提供重置命令，并在禁区写明不得删改的范围 |
| 可写目录与外部副作用 | 运行时会写入的目录；会触达的外部系统与是否允许在验收中触发 |
| 观测手段 | 界面：URL（验收用用户自己的 Chrome，写明依赖的登录态与账号来源）、CLI 调用方式或桌面应用的观察手段；日志：文件或命令；数据：查询命令；文件：目录 |
| 禁区 | 不得触碰的数据、服务、目录与账号；浏览器复用真实登录态时，列出不得在验收中触发的外部站点与操作（如向第三方真实发送、付费、登出） |

只写本项目实际存在的条目，没有的通道不要编。配置项与密钥引用位置，不写值。

## 缺失时的起草

1. 证据来源：根 `justfile` 与各 stack 的 recipe、README 的运行说明、`docs/operations/`、配置文件与 `.env.example`、进程入口（`main`、`bin/`、`package.json` 的 scripts）。
2. 能从证据确定的写成事实；确定不了的（如就绪判定、禁区）在草稿里标 `未知`，由阶段 1 的一次确认让用户补充，不自行假设。
3. 没有后台化的启动命令时，草稿里提出一个 recipe 方案（如 `serve-start` 用 `nohup` 写日志与 pid、`serve-stop` 读 pid 结束进程组），经用户确认后与契约一起写入项目并 commit；不在确认前改 justfile。
4. 没有重置命令且项目有持久数据时，草稿写“未重置”，验收断言只用本次运行产生的数据；用户想要重置命令时按其说明实现并确认。
5. 草稿替换 `<待填 按需：…>` 标记写入该节，保留节标题，不改其他节。
