# 环境契约

目标项目的 `docs/development/local-acceptance.md` 整页就是契约。本文规定它要回答什么，以及缺失时怎样起草。

## 契约要回答的问题

| 问题 | 要求 |
| --- | --- |
| 运行形态 | web 服务、CLI、后台任务、桌面应用或其组合；没有可运行形态就写明，此时只能走命令输出与文件 |
| 启动与停止 | 命令（通常是 mise task）；就绪判定（端口、健康检查 URL、日志关键字或命令退出）；日志与 pid 文件位置。启动命令自行后台化（`nohup`/`setsid` 加 `&`），stdout 与 stderr 全部重定向到日志文件后立即返回，否则 agent 的前台调用会挂到超时。停止命令结束全部子进程（按进程组或 pid 文件） |
| 数据 | 存储类型与位置或连接方式、查询命令、重置命令；没有持久数据写“无”。验收会写入并重置数据，所以指向验收专用的数据目录与库；只能用日常数据时不提供重置命令，并在禁区写明不得删改的范围 |
| 可写目录与外部副作用 | 运行时写入的目录；会触达的外部系统及是否允许在验收中触发 |
| 观测手段 | 界面：URL（写明依赖的登录态与账号来源）、CLI 调用方式或桌面应用的观察手段；日志：文件或命令；数据：查询命令；文件：目录 |
| 禁区 | 不得触碰的数据、服务、目录与账号；复用真实登录态时，不得触发的外部站点与操作（如向第三方真实发送、付费、登出） |

只写项目实际存在的条目。配置项与密钥写引用位置，不写值。

## 缺失时的起草

1. 证据来源：根 `mise.toml` 与 `mise-tasks/`、README 的运行说明、`docs/operations/`、配置文件与 `.env.example`、进程入口（`main`、`bin/`、`package.json` 的 scripts）。
2. 证据能确定的写成事实；确定不了的（如就绪判定、禁区）标 `未知`，由阶段 1 的确认让用户补。
3. 没有自行后台化的启动命令时，草稿提出 mise task 方案（如 `serve-start` 用 `nohup` 写日志与 pid、`serve-stop` 读 pid 结束进程组），确认后与契约一起写进 `mise.toml`。
4. 有持久数据但没有重置命令时，草稿写“未重置”；用户想要重置命令时按其说明实现。
5. 起草整页。文件存在且是 `<待填` 标记时，替换标记，保留页头与标题。文件缺失时新建：页头照 `docs/development/` 下其他页面（同目录页面带 `summary`、`read-when` 等元数据块时照样补齐，生成索引依赖它）；正文第一句说明本页是 `/acceptance` 的环境契约；在 `docs/development/workflow.md` 加一句指向本页的链接，登记到 development 目录索引（没有时登记到 `docs/INDEX.md`）；项目有索引生成或文档检查命令时运行它。
6. 确认后写入的契约与 task 改动一起单独 commit。
