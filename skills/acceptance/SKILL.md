# 真实环境验收

本 skill 安装在用户级，对调用时当前工作目录的项目生效。它做的是 QA 在真实环境上按功能清单过一遍的事：以项目的行为文档为预期，在本机启动真实的运行形态，按项目声明的观测手段逐项验证，发现偏差就修，修到一次零修复的全量通过为止，最后留下验收记录。一次运行不可重复执行；沉淀下来的是修复 commit、随修复补的自动化测试和报告。

可选参数 `<topic>`：只验 `docs/behaviors/<topic>.md`（或同名模块页）描述的行为，完成条件相应缩到该主题。参数只取第一个词作为 topic，其余文字（如 goal 条件的剩余部分）忽略。

`references/` 下的文件在链接它的步骤到达时再读。

## 与 /goal 配合

一次验收通常持续几十轮，推荐由用户用 goal 驱动（skill 自己不能设 goal）：

```text
/goal /acceptance 直到打印"验收完成"，最多 80 轮
```

主题模式写 `/goal /acceptance <topic> 直到打印"验收完成"，最多 40 轮`。`验收完成` 这一行只在阶段 5 全部条件满足后打印；中途每轮结束的摘要固定以 `验收进行中` 开头，中途的摘要与叙述里不要出现“验收完成”四个字连写，避免评估器误判。更短的 `/goal /acceptance` 未经验证：评估器拿不到判据，可能首轮就判完成。不用 goal 直接 `/acceptance` 也能运行，只是每次停下需要用户说“继续”。

## 不做假设

- 不假设项目有浏览器界面、数据库、网络服务或桌面应用。被验对象可能是 web 服务、CLI、后台任务、库的示例程序或桌面 app。界面是什么、数据存在哪、怎么观察，一律以环境契约为准：契约没声明的通道不发明，不额外起浏览器去找界面，不猜数据库连接串。
- 契约声明 web 界面时用用户自己的 Chrome（Claude in Chrome 扩展，`mcp__claude-in-chrome__*`，延迟加载时先用 ToolSearch 一次加载全部所需工具）：最接近真实使用环境，复用已有登录态，还能读 console 与 network。代价是它操作的是真实浏览器与真实账号，所以只访问契约声明的地址，只在自己新建的标签页里操作，不动用户的其他标签页，不登出、不改浏览器设置，不另起 Playwright 等独立浏览器。桌面应用只用契约声明的手段；没有手段的通道记为“无法观测”，不记为通过。
- 账本是跨轮唯一真相：每轮开始先读账本再行动；对话被压缩后以账本为准，不凭记忆续跑。

## 阶段 0：前提与输入（只读）

1. 当前目录是 Git 工作区根目录，且工作树干净。有未提交改动时停下：修复会逐个 commit 到当前分支，脏工作树会混入无关改动；让用户先提交或暂存。
2. 预期来源：`docs/behaviors/*.md`，其次 `docs/architecture/modules/*.md` 的“当前行为规格”章节。两处都没有可用内容时停下说明“没有可验收的预期”，不读代码编预期。给了 `<topic>` 时只取对应文件；找不到就停下列出可选主题。
3. 环境契约：目标项目的 `docs/development/local-acceptance.md` 整页，只认这一个路径，内容要求见 [references/environment.md](references/environment.md)。文件缺失或仍是 `<待填` 标记时，按该文件从 justfile、README 与配置起草整页，纳入阶段 1 的一次确认；契约声明的命令不存在或运行失败是硬阻塞。
4. 观测工具：契约声明 web 界面时先调用 `tabs_context_mcp` 确认 Chrome 扩展已连接，未连接是硬阻塞，提示用户打开 Chrome 并确认 Claude in Chrome 扩展在线；其他通道按契约声明的命令逐个核对可执行。
5. 账本：在会话临时目录（有 scratchpad 时用它，否则 `mktemp -d`）建 `ledger.md`，把路径打印到对话；格式见 [references/checklist.md](references/checklist.md#账本)。

## 阶段 1：清单与一次确认

1. 按 [references/checklist.md](references/checklist.md) 从预期来源推导验收项：每项有来源（文件与章节）、前提、操作、各通道的预期观察。文档没写的功能不列入清单，记入账本的“未覆盖”段供报告。
2. 把清单、（如有）契约草稿、将要执行的数据重置动作写入账本，用一次 AskUserQuestion 请用户确认：按清单执行，或指出要调整的项。此后不再因清单或契约提问。用户调整后更新账本。
3. 契约草稿经确认后写入 `docs/development/local-acceptance.md`（文件缺失时新建并接入文档索引，做法见 [references/environment.md](references/environment.md#缺失时的起草)），单独 commit。

## 阶段 2：环境就绪

1. 契约有数据重置命令就执行；没有时在现有数据上验收，账本记“未重置”，断言只用本次运行产生的数据。
2. 用契约的启动命令启动，等待契约的就绪条件。启动命令必须自行脱离本会话（后台化、全部输出重定向到日志文件、记录 pid），用 Bash 工具前台调用它；不用 Bash 工具的后台模式，否则 goal 的每轮评估都会被跳过。就绪超时是硬阻塞。
3. 记录基线：日志文件当前长度、契约声明的数据检查命令的输出、可写目录的文件清单。之后每项的证据都相对基线取增量。
4. 有 web 界面时用 `tabs_create_mcp` 新建一个标签页专用于验收，记下 tab id，并告知用户运行期间不要操作这个标签页；全程只用这个标签页（需要多窗口的行为再按需新建并记录），阶段 5 结束时关闭自己开的标签页。

## 阶段 3：逐项验收

每项按顺序：执行操作 → 在契约声明的每个通道取证（界面：页面文本或截图、命令输出，web 界面另读该标签页的 console 错误与失败的 network 请求；日志：新增行；数据：查询结果；文件：目录变化；外部副作用：契约给的检查方式）→ 对照预期 → 账本写 PASS 或 FAIL 并附证据摘要。预期里没提但观察到的 console 错误或 5xx/4xx 响应记入账本“疑点”，不单凭它判 FAIL。串行执行；只读的定位与分析可派子 agent，操作环境的动作不并行。

证据标准：零输出、零匹配、“没有报错”不算通过；预期涉及的通道无法观测时记“无法观测”并留到报告，不记 PASS；预期与观察只有措辞差异时按语义判，有实质差异时判 FAIL 并写明差在哪。

一轮尽量做到无法继续（硬阻塞、需要提问或本阶段完成）才停下，不为了“汇报进度”提前停。每次停下前：先写账本，再打印摘要——`验收进行中`、总数、PASS、FAIL、FIXED、DEFERRED、剩余、本轮修复数、账本路径。

## 阶段 4：偏差处理

对每个 FAIL 先定位原因，再按下面判定：

- **文档问题**：文档与代码冲突且该改的是文档（规则不合理、已被后续决定替代、自相矛盾）→ DEFERRED，按 `docs/agents/issue-tracker.md` 的约定写票，不改文档、不改代码迁就文档。
- **就地修复**的条件：改动局部在一个模块内，不改数据 schema，不改公共接口或配置键，不涉及设计取舍。不满足任一条 → DEFERRED 写票，继续下一项。
- 修复流程：先按项目的测试分层约定（有 `docs/agents/testing.md` 时依其规则归入 core 或 full）补一个重现该缺陷的失败测试，纯界面表现类可免并在账本注明理由；然后修复，运行相关测试与 `just gate-core`（有则跑，失败如实记录），一处修复一个 commit 到当前分支，message 引用验收项编号。需要重启的用契约的停止与启动命令；修复涉及数据写入的先重置再重跑。
- 重跑范围：该项加上同一来源文件（同一 behaviors 主题或同一模块页）的全部项；通过后状态记 FIXED。
- **硬阻塞**，停下问用户：服务起不来或就绪超时；缺凭证、Chrome 扩展断开或缺 MCP 工具；浏览器被原生对话框（alert/confirm）阻塞，需要用户手动关闭；需要契约未授权的破坏性操作；文档自相矛盾且影响主流程；修复需要 schema 变更或跨模块重构；同一项修复两次仍失败。提问时附账本路径与当前摘要，用户答复后从账本继续。

## 阶段 5：收敛与报告

1. 所有项都是 PASS、FIXED 或 DEFERRED 后，如本次运行有过任何修复：重置数据（契约有命令时）、重启服务、全量重跑一遍（主题模式只重跑该主题），要求零修复。重跑中又需要修复就回阶段 4，然后再来一次。
2. 用契约的停止命令停止服务，确认进程已退出、没有残留的子进程；关闭自己新建的浏览器标签页。
3. 报告写入 `docs/research/acceptance/<topic 或 all>-<YYYY-MM-DD>.md`（同日已有则加 `-2`、`-3`），格式用 [templates/report.md](templates/report.md)；在 `docs/research/INDEX.md` 的“验收记录”登记一条；单独 commit。
4. 打印最终摘要：结果计数、修复 commit 列表、票据列表、报告路径，末行单独一行 `验收完成`。只有报告 commit 之后才能打印这一行。

## 边界

- 不改文档迁就代码、不弱化预期、不跳过项；无法观测与未覆盖如实进报告。
- 不 push、不开 PR、不切换分支、不改写历史。
- 不操作契约禁区；浏览器里只访问契约声明的地址、只动自己新建的标签页，不登出、不改浏览器设置、不触碰用户的其他标签页与账号。
- 发现与验收项无关的缺陷只写票，不顺手修。
