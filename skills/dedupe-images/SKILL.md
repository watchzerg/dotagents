# 图片库去重

脚本 `scripts/dedupe_images.py` 负责扫描、提供材料和执行，执行前都会按 SHA-256 复核，不会删除在别处没有相同内容的文件。模型负责抽查有把握的部分、判断拿不准的案例。需要 `python3` 为 3.14+，只用标准库；支持 macOS 15+（系统自带 `/usr/bin/trash`）与 Linux（FreeDesktop 回收站）。下文 `<脚本>` 指该脚本的完整路径，`<临时目录>` 用会话临时目录，计划与决策文件都不写进图片库。

## 步骤

1. **确定总目录**：取用户给出的路径；没给就问，不猜。
2. **生成计划**（不改动文件，大库在移动硬盘上可能要几分钟）：

   ```sh
   python3 <脚本> plan "<总目录>" --out "<临时目录>/plan.json"
   ```

   把摘要转给用户：自动处理部分的数量与体积，以及交给模型判断的案例数。
3. **抽查自动部分**：

   ```sh
   python3 <脚本> show "<临时目录>/plan.json" --sample 5
   ```

   逐条看样本，检查：移走后编号有没有出现空缺（例如只剩 `01…09` 而 `10…` 被移走且没有对应的保留项）；保留下来的文件名或目录名不比移走的差；目录级的保留目录确实是更完整的那份；“移走超过一半图片的目录”逐个看是否合理。有疑问就读计划 JSON（`dir_removals[]`，`dirs[].groups[]` 的 `keep`、`remove`、`rename_to`、`match`）或列目录核对。
   - 没有问题：直接执行，不用再问用户。
   - 发现问题：不执行，把问题和样本告诉用户。这说明脚本规则有漏洞，应该修脚本，不要手工绕过。
4. **执行自动部分**：

   ```sh
   python3 <脚本> apply "<临时目录>/plan.json"
   ```

   apply 先移整目录（并删除因此变空的上级目录），再处理文件级各组；计划之后有变动的目录或组整个跳过。把数量、体积、跳过项和失败项如实转述。退出码 1 表示有失败项，2 表示计划不可用或平台不支持（未改动任何文件）。
5. **判断案例**：用 `show "<临时目录>/plan.json" [编号 ...]` 取材料，不给编号则输出全部。案例多（几十个以上）时按编号分批交给子 agent 并行判断，每个子 agent 只拿到编号、本节规则和输出格式，返回决策与理由，主 agent 汇总并抽看理由。判断依据：
   - **目录案例**（`= ` 为内容相同，`⊂` 为子集）：看命名、编号范围与缺号、目录名、所在合集结构。保留命名更规范、合集更完整、目录名信息更全的一方；被包含的一方只是另一方的不完整副本时移走它；两个合集大部分相同时，可把一方独有的子目录移进另一方再整体移走；单章与合集、旧版与新版、整理好的单本与杂图包这类各有用途的，通常保留两边（`keep`），除非一方明显没有独立价值。
   - **文件案例**（同名同体积、内容不同）：先看材料里的损坏特征与不同字节的位置；仍判断不了时可以打开两张图对比，每次运行最多看 10 个案例，在给用户的表里注明看过图。画面不同就两份都留。
6. **给用户确认**：列一张表，每个案例一行：编号、涉及的目录或文件、建议（移走哪个、移动什么、保留）和一句理由；`keep` 也列出来。用户可以逐条改。
7. **执行决策**：按用户确认后的结果写决策文件，再执行：

   ```json
   {
     "root": "<总目录的绝对路径>",
     "actions": [
       {"case": "c012", "op": "move", "src": "A合集/独有的一话", "dest": "B合集"},
       {"case": "c012", "op": "trash", "path": "A合集", "keep": ["B合集"]},
       {"case": "c013", "op": "keep"}
     ]
   }
   ```

   ```sh
   python3 <脚本> apply-decisions "<临时目录>/decisions.json"
   ```

   路径相对总目录。`move` 把 `src` 移进已存在的目录 `dest`，目标里不能有同名项；`trash` 的 `path` 可以是目录或文件，`keep` 列出它的内容所在的保留路径。同一案例的操作一起校验：被移走路径下每个非隐藏文件都要在 `keep` 下（含移进 `keep` 的目录）有 SHA-256 相同的文件，`keep` 不能在被移走的路径里；任何一项不满足，整个案例跳过、不做改动。执行顺序是先移动、再移入回收站、再删除变空的上级目录。把执行数、跳过的案例及原因如实转述。

## 约束

- 不手工删除、移动或改名图片，不编辑计划 JSON；所有改动通过 `apply` 和 `apply-decisions` 完成。
- 案例的决策必须经用户确认后才执行；自动部分在抽查无问题后执行。
- 自动部分执行后目录又有改动，或距 plan 已久，先重新运行 plan 再判断案例。
