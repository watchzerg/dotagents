# 图片库去重

判定与执行全部由脚本 `scripts/dedupe_images.py` 完成，本 skill 只负责调用、展示计划、取得确认和转述结果。需要 `python3` 为 3.14+，只用标准库；支持 macOS 15+（系统自带 `/usr/bin/trash`）与 Linux（FreeDesktop 回收站）。

## 步骤

1. **确定总目录**：取用户给出的路径；没给就问，不猜。脚本递归处理总目录及其下每个目录，每个目录只比较自己直接包含的图片；隐藏目录、符号链接和含程序文件的软件目录（连同子目录）跳过。页码序列（如 `page (1).jpg…page (95).jpg`）只在同一页码内去重，不同页码的同内容文件仅在补零与不补零两套编号整套重复时移走一套，序列内不改名。名称对不上的重复另按三种命名对应识别，都要求内容哈希相同：只差补零（`0630_A_76.png` 与 `630_A_76.png`），只差开头流水号且整套存了两遍（`001_hellven_000.jpg` 与 `121_hellven_000.jpg`），两种命名模板整套对应（`01.jpg…` 与 `page (001).jpg…`，可错开编号）；零星几对、小套不动，也不改名。
2. **生成计划**：计划文件写到临时目录，不写进图片库。

   ```sh
   python3 "<skill目录>/scripts/dedupe_images.py" plan "<总目录>" --out "<临时目录>/dedupe-plan.json"
   ```

   plan 不改动任何文件。把脚本输出的摘要原样转给用户：按一级目录汇总的删除与改名数量（改名包括单独存在的副本，如目录里只有 `a (3).jpg` 时改为 `a.jpg`）、待释放体积、需人工确认清单、跳过的软件目录、读取出错项，以及其中按命名对应识别的数量（这些待删文件与保留项名字不同，计划组的 `match` 为 `zero_pad`、`index_prefix` 或 `name_set`）。用户要看具体文件时，从计划 JSON 的 `dirs[].groups`（`keep`、`remove`、`rename_to`）中摘取。
3. **等待确认**：明确问用户是否执行，得到肯定答复才继续。需人工确认项（同名同体积、内容不同且判不出哪个损坏）脚本不会删除，只列给用户自行查看；不要打开图片做对比。
4. **执行计划**：

   ```sh
   python3 "<skill目录>/scripts/dedupe_images.py" apply "<临时目录>/dedupe-plan.json"
   ```

   apply 会逐个复核计划中的文件，计划之后有变动的组整组跳过。把移入回收站的数量与体积、改名数，以及每个跳过项和失败项如实转述；退出码 1 表示有失败项，2 表示计划不可用或平台不支持（此时未删除任何文件）。

## 约束

- 不手工删除、移动或改名图片，不编辑计划 JSON；用户想调整范围时，改总目录后重新运行 plan。
- 用户确认之后目录又有改动，或距 plan 已久，先重新运行 plan 再执行。
