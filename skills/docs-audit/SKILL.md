# 文档漂移审计

本 skill 安装在用户级，对调用时当前工作目录的项目生效。`just docs-check` 只查链接、结构与 `covers` 是否匹配文件，查不出“正文写的和代码不符”；本 skill 逐条对照源码补这一缺口。

## 约定来源

动手前读 `docs/agents/documentation.md` 的随交付同步、体量预算与拆页、模块页模板与行为规格模板；规则以该页为准，本 skill 只给步骤。建票据按 `docs/agents/issue-tracker.md`，标签按 `docs/agents/triage-labels.md` 映射。

页面与源码的映射取页首 frontmatter 的 `covers`（仓库根相对的 glob）。项目没有 `covers` 时，按源文件名与目录名在 `docs/architecture/` 下搜索归属页，并在报告注明“无 covers 映射”。

## 参数与模式

- 不传参数：抽样模式，随机抽 3 页。
- 传页数或页面路径（相对仓库根）：抽样模式，抽该页数或只审这些页。
- 传基准（commit、分支或 tag）：diff 模式，核对相对基准的改动（含未提交与未跟踪文件）命中的页面。

参数是存在的 `.md` 路径即页面，纯数字即页数，其余按 git 引用解析；解析不了就停下问用户。

## 抽样模式

1. **抽页。** 传了页面就审这些页；否则从页首 frontmatter 带 `covers` 的页面中随机抽（只认页首，正文示例里的 `covers:` 不算）：

   ```sh
   awk 'FNR==1{fm=($0=="---");next} fm&&/^---$/{fm=0} fm&&/^covers:/{print FILENAME;fm=0}' $(find docs -name '*.md') | sort -R | head -n 3
   ```

   行为规格不直接抽：其中的顺序与数值经被抽模块页的“当前行为规格”或链接一并核对。
2. **列陈述。** 逐页只列可由代码证伪的两类：
   - **顺序**：步骤列表、“先……再……”、等待点、失败后的收敛与退出顺序、参与者顺序。
   - **数值**：上限、默认值、超时、容量、尺寸、计数（如“几个使用方”“几类”）、阈值与单位。

   定义、理由、已知限制等不能直接由代码证伪的句子跳过。指向其他页的链接只核对链接处这一句，不顺带审被链接页。
3. **对照源码。** 每页派一个只读子 agent 完成第 2、3 步，简报带上两类陈述的口径与[判定](#对照与判定)，要求逐条返回“页面:行、陈述、源码文件与符号、判定”和精确条数。主 agent 并行做第 4 步，子 agent 返回后回到源码复核每条非“一致”的结论，再进入[处理](#处理)。
4. **复核索引。**
   - `docs/research/INDEX.md` 每一行：去向链接指向的页面仍持有该结论时状态成立；页面已拆分或移动时改指现在持有内容的页面；结论已被正文或 ADR 吸收、或被推翻时更新状态与去向。
   - ADR：核对每条的状态是否仍符合现状，例如已被后来的 ADR 或正文推翻、项目状态取值区分采纳与实现而决定已落地。索引由脚本生成，或 `docs-check` 已校验索引与 frontmatter 一致时，不再逐条比对两者；否则逐条比对状态、日期与取代关系。

   只改索引行与元数据，历史证据正文一字不改。索引不存在就跳过并在报告注明。

## diff 模式

1. **找页面。** 运行 `just docs-affected <基准>`，得到改动命中 `covers` 的页面。没有该 recipe 时用 `git diff --name-only <基准>` 加 `git status --short` 列改动，自行按 `covers` 匹配。
2. **找缺口。** 对照改动列表，产品源码文件（不含文档、测试与配置）未被任何页面 `covers` 命中的，列为“无归属页”，不猜归属。
3. **列陈述。** 对每个命中页，读命中文件的 diff，核对页面中与这些改动相关的陈述：入口与符号、状态与计数、顺序与数值、失败／取消／恢复路径、事务与锁、“代码与验证入口”列出的命令与测试目录。改动改变了用户可观察结果时，同样核对对应的行为规格。
4. **对照源码**，按[判定](#对照与判定)逐条给结论。

## 对照与判定

- 证据只认实际代码：调用顺序、常量、默认参数、分支条件。不以注释、测试名或其他文档为证。
- 每条陈述判定为下列之一；判定“一致”也记下核对到的源码文件与符号：
  - **一致**。
  - **文档错**：代码意图明确，正文落后或写错。两处正文互相矛盾而代码支持其中一处时，另一处判为文档错。
  - **代码注释错**：正文与实现一致，代码注释与实现不符。
  - **需产品判断**：代码与正文不符，无法确定以谁为准。
  - **正文冲突**：两处正文互相矛盾，代码无法判定谁对。
- 委派子 agent 核对时，把“每条结论附源码文件与符号”作为交付标准；只有页面引文、没有代码事实的结论不算完成。

## 处理

- **文档错**：按随交付同步就地改正文，同步受影响的行为规格、功能地图与入链；不顺带重写无关段落。改后超出体量预算的按拆页规则处理。
- **代码注释错**、**需产品判断**、**正文冲突**：不改产品代码，冲突的正文原样保留；每项在 tracker 建一张票据，附差异行与源码位置（正文冲突附两处原文位置）。代码注释错标 `ready-for-agent`，其余两类标 `needs-triage`。项目没有 tracker 约定时只列在报告里。
- 核对中顺带发现的代码缺陷（与正文无关的 bug）同样只建票据、标 `needs-triage`，附复现或代码路径，在报告里与差异表分开列。
- 改过文档就运行 `just docs-check`，修到通过。

## 报告

- 模式与范围：审了哪些页（diff 模式写明基准），每页与合计核对的陈述条数。
- 差异表，只列不一致项；没有差异时写“未发现差异”：

  | 页面:行 | 陈述 | 代码事实（文件与符号） | 判定 | 处理 |
  | --- | --- | --- | --- | --- |

- 顺带发现的代码缺陷及票据。
- diff 模式：无归属页的源文件。抽样模式：索引中改动或存疑的行。
- 已改的文档及要点、新建的票据编号、`just docs-check` 结果。

由票据发起审计时，同一内容记入该票据评论。不自动提交或推送。
