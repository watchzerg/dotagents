# 文档漂移审计

`mise run docs-check` 只查链接、结构与 `covers` 是否匹配文件；本 skill 对当前工作目录的项目逐条对照源码，查正文与代码是否相符。

## 约定来源

动手前读 `docs/agents/documentation.md` 的随交付同步、体量预算与拆页、模块页模板与行为规格模板；规则以该页为准。票据按 `docs/agents/issue-tracker.md` 建，标签按 `docs/agents/triage-labels.md` 映射。

页面与源码的映射取页首 frontmatter 的 `covers`（仓库根相对的 glob）。项目没有 `covers` 时，按源文件名与目录名在 `docs/architecture/` 下搜归属页，报告注明“无 covers 映射”。

## 参数与模式

- 无参数：抽样模式，随机抽 3 页。
- 纯数字：抽样模式，抽该页数。
- 存在的 `.md` 路径（相对仓库根）：抽样模式，只审这些页。
- 其余按 git 引用（commit、分支或 tag）解析为基准：diff 模式，核对相对基准的改动（含未提交与未跟踪文件）命中的页面。解析不了就停下问用户。

## 抽样模式

1. **抽页。** 未指定页面时，从页首 frontmatter 带 `covers` 的页面随机抽（正文示例里的 `covers:` 不算）：

   ```sh
   awk 'FNR==1{fm=($0=="---");next} fm&&/^---$/{fm=0} fm&&/^covers:/{print FILENAME;fm=0}' $(find docs -name '*.md') | sort -R | head -n 3
   ```

   行为规格不单独抽，其中的顺序与数值经被抽模块页的“当前行为规格”或链接一并核对。
2. **派核对子 agent。** 每页派一个只读子 agent，列出该页陈述并按[判定](#对照与判定)逐条对照源码，返回“页面:行、陈述、源码文件与符号、判定”及精确条数。只列两类可由代码证伪的陈述：
   - **顺序**：步骤列表、“先……再……”、等待点、失败后的收敛与退出顺序、参与者顺序。
   - **数值**：上限、默认值、超时、容量、尺寸、计数（如“几个使用方”“几类”）、阈值与单位。

   定义、理由、已知限制等跳过。链接到其他页的句子只核对这一句，不顺带审被链接页。
3. **复核索引**（与第 2 步并行，主 agent 做）。只改索引行与元数据，历史证据正文一字不改；索引不存在就跳过并在报告注明。
   - `docs/research/INDEX.md` 每一行：去向页面仍持有该结论则成立；页面拆分或移动则改指现在持有内容的页面；结论已被正文或 ADR 吸收、或被推翻时更新状态与去向。
   - ADR：核对每条状态是否符合现状，例如已被后来的 ADR 或正文推翻，或项目状态区分采纳与实现而决定已落地。索引由脚本生成、或 `docs-check` 已校验索引与 frontmatter 一致时，跳过两者的逐条比对；否则逐条比对状态、日期与取代关系。
4. **复核子 agent 结论。** 回到源码复核每条非“一致”的结论，再进入[处理](#处理)。

## diff 模式

1. **找页面。** `mise run docs-affected <基准>` 列出改动命中 `covers` 的页面。没有该 task 时用 `git diff --name-only <基准>` 加 `git status --short` 列改动，自行按 `covers` 匹配。
2. **找缺口。** 改动中的产品源码文件（不含文档、测试与配置）未被任何页面 `covers` 命中的，列为“无归属页”，不猜归属。
3. **列陈述。** 对每个命中页读命中文件的 diff，列出页面中与改动相关的陈述：入口与符号、状态与计数、顺序与数值、失败／取消／恢复路径、事务与锁、“代码与验证入口”列出的命令与测试目录。改动改变了用户可观察结果时，一并列对应行为规格的陈述。
4. **对照源码**，按[判定](#对照与判定)逐条给结论。

## 对照与判定

证据只认实际代码：调用顺序、常量、默认参数、分支条件；注释、测试名与其他文档都不算。每条结论附核对到的源码文件与符号，“一致”也不例外；子 agent 只给页面引文、没有代码事实的结论退回重做。

每条陈述判为下列之一：

- **一致**。
- **文档错**：代码意图明确，正文落后或写错。两处正文矛盾而代码支持其中一处时，另一处是文档错。
- **代码注释错**：正文与实现一致，代码注释与实现不符。
- **需产品判断**：代码与正文不符，无法确定以谁为准。
- **正文冲突**：两处正文矛盾，代码判定不了谁对。

## 处理

- **文档错**：按随交付同步就地改正文，同步受影响的行为规格、功能地图与入链；只改出错的句子。改后超出体量预算的按拆页规则处理。
- **代码注释错**、**需产品判断**、**正文冲突**：产品代码与冲突正文原样保留，每项建一张票据，附差异行与源码位置（正文冲突附两处原文位置）。代码注释错标 `ready-for-agent`，其余两类标 `needs-triage`。项目没有 tracker 约定时只列在报告里。
- 顺带发现的与正文无关的代码缺陷：建 `needs-triage` 票据，附复现或代码路径，报告中与差异表分开列。
- 改过文档就运行 `mise run docs-check`，修到通过。

## 报告

- 模式与范围：审了哪些页（diff 模式写明基准），每页与合计核对的陈述条数。
- 差异表，只列不一致项；没有差异写“未发现差异”：

  | 页面:行 | 陈述 | 代码事实（文件与符号） | 判定 | 处理 |
  | --- | --- | --- | --- | --- |

- 顺带发现的代码缺陷及票据。
- diff 模式：无归属页的源文件。抽样模式：索引中改动或存疑的行。
- 已改的文档及要点、新建的票据编号、`mise run docs-check` 结果。

由票据发起审计时，同一内容记入该票据评论。改动留在工作树，提交与推送交给用户。
